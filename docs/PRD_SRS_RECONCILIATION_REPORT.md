## 2. Major Architectural Changes

Rancangan awal berubah menjadi monolit Laravel dengan API eksternal, observasi kumulatif, pemrosesan bertahap dan model ML lokal. MySQL adalah basis nyata migration/testing, bukan database yang dapat dipertukarkan dengan PostgreSQL tanpa verifikasi. Gemini menangani teks AI; Python hanya inferensi risiko yang diuraikan. Klien portal bukan User internal. Peran Docker all/web/worker/scheduler tersedia; keberadaan konfigurasi bukan bukti deployment berjalan.

## 3. Role & Permission Changes

PermissionSeeder membentuk 55 pasangan katalog dari 11 modul × 5 tindakan. Tujuh role final: CEO, Manager, SMO, Copywriter, Content Creator, Graphic Designer, Admin. Role digabung melalui user_roles, bukan satu role_id. CEO/Manager/Admin global; staf lain memakai roster. Admin hanya mendapat view pada katalog, tetapi endpoint pribadi/laporan tetap memutasi. Form publikasi CEO/SMO dan Kanban workflow:update mempunyai hak berbeda. Matriks SRS §6 mencatat tindakan backend satu per satu.

## 4. Workflow Changes

Sembilan status normal menggantikan planned/in_design. Draft keluar lewat release batch; Jobdesk Tambahan/bulk AI dibuat Brief Ready. Revision loop open→in_progress→resolved terhubung perpindahan konten. Setuju klien mengisi cap review dan tetap waiting_review; internal approve membutuhkan permission dan tidak ada revisi terbuka, tetapi tidak menuntut Setuju klien. Terminal normal dapat dioverride koreksi CEO/Manager dengan alasan, tanpa rekonstruksi seluruh fakta turunan.

## 5. Content Planning Changes

Paket aktif menghasilkan slot C/D Video/Desain sesuai snapshot kuota. Slot dilengkapi informasi, multi-platform dan brief, diajukan, diputuskan, lalu diberi deadline sebelum dilepas. Rejected dapat dibuka kembali tanpa menghapus log lama. PIC/talent/properti bukan syarat lengkap pengajuan; Link Konten (Draft) bukan prasyarat waiting_review pada HEAD. Keunikan klien/bulan/tahun hanya guard aplikasi, dan pembuatan plan/slot belum seluruhnya transactional. Kalender memakai deadline kerja, bukan semua tanggal yang bernama posting.

## 6. Analytics Changes

Performa memilih satu klien, platform dan Bulan/Rentang. Data API dipilih berdasarkan published_at genuine; data CSV menurut metric_date. Nilai terkini cohort dapat berubah setelah bulan tersebut berakhir. Pertumbuhan memerlukan baseline/observasi; gap harian tidak diisi angka fiktif. Coverage full/partial/unavailable dan data-through tidak identik dengan “sync baru diklik”. Performa dapat memuat post unmatched, sementara konsumen yang membutuhkan contentItem tidak selalu memuatnya. Aggregate all-null tertentu tetap dapat menghasilkan nol; jangan menjanjikan semua nol pasti hasil pengukuran.

CSV performa menggunakan judul ter-normalisasi dalam klien, bukan external ID; judul ambigu dapat memilih pertama, angka dicast, platform asing dilewati. CSV bukan backfill snapshot D+7. Sumber audiens dipisah; keterbatasan TikTok bukan data nol. Default rolling sync 90 hari mempertahankan data lama tanpa terus merefresh seluruh arsip.

## 7. AI Changes

AI Brief mempunyai alur manual, generasi/bantuan field, diskusi, allowlist Apply, previous_snapshot dan finalisasi. AI tidak menentukan tanggal kerja/upload. Feasibility berbasis Gemini bukan verifikasi deterministik kapasitas.

AI Strategy memakai bulan analisis/platform, history/chat/refine/ide; skor Potensi dihapus. Apply per-idea mengubah draft yang sudah ada, tetapi endpoint bulk Apply masih aktif dan membuat brief_ready baru dengan PIC/jadwal. Revert lama membutuhkan applied_at, menjaga hasil yang sudah diproses dan melakukan soft delete hasil, bukan undo edit slot. Ini bukan penghapusan legacy yang sudah selesai.

Delay Risk memakai model probabilitas tersimpan dan tujuh fitur. Workload bernama mingguan tidak benar-benar dibatasi minggu pada query; top_factor heuristic bukan penjelasan SHAP. Panel evaluasi memakai prediksi sebelum uploaded pertama dan tidak sama dengan KPI pegawai. Tidak dilakukan validasi akurasi end-to-end.

## 8. Team/KPI Changes

KPI bulanan menggantikan ringkasan workload sebagai satu-satunya penilaian tim. Cohort memakai publikasi pertama, atribusi union assignment/brief creator/log actor scheduled/uploaded, dedupe item per user. Dasar 60% ketepatan dan 40% kualitas, bonus maksimal 10, nilai akhir maksimal 100. Data ketepatan hilang menyesuaikan denominator/bobot; revisi klien tidak mengurangi kualitas; CSV-only tidak memberi bonus snapshot D+7. Hasil sampel kecil berlabel sementara.

Tren enam bulan, perbandingan anggota dan profil tersedia. Kalkulasi halaman dapat memicu bulan historis yang diminta. Pengambilan snapshot D+7 tidak memfilter platform, kalkulasi tanpa kontribusi tidak menghapus hasil lama, dan filter populasi tren tidak identik dengan daftar anggota; dicatat sebagai Q-08.

## 9. Integration Changes

Google login memakai whitelist akun; Instagram bisnis memakai OAuth/state/insights; TikTok memakai Login Kit/Display API v2 dan state/PKCE. Token terenkripsi dan hidden tersedia. TikTok challenge pada kode berbentuk hex; dokumentasi integrasi lama menyebut base64url. Provider live belum diuji, sehingga tidak diputuskan bahwa mock test membuktikan penerimaan provider.

Pipeline mempunyai run/task/item/failure, chunks, retry, known refresh dan matching. Auto-sync terdaftar satu kali sehari default 03:15; refresh token tengah malam. Prune snapshot otomatis belum aktif. Fonnte/SMTP pengiriman laporan/undangan tidak ditemukan sebagai integrasi fitur aktual. Aplikasi tidak melakukan direct social posting.

## 10. Data Model Changes

ERD lama diganti dengan schema final: multi-role, roster, snapshot paket, slot, platform pivot, format, dua jenis aktor log/revisi, cap review, publikasi multi-platform, raw identity dan observasi harian, audience source, run/task/item/failure, AI history/message, risk, KPI dan attendance. SRS §7 mencantumkan field penting, semua FK keluar, unique database dan kebijakan histori/penghapusan.

Guard controller tidak dinyatakan sebagai unique DB. Soft delete tidak digeneralisasi dari content_items ke semua tabel; client berhistori menjadi paused. Log tidak dianggap immutable hanya karena tidak ada tombol edit. File laporan tetap objek storage terpisah dari row generated_reports.

Form final membedakan type/format/platform, link referensi/link hasil/URL tayang. “Tambah Konten” biasa diganti slot dan Jobdesk Tambahan; “Undang User” diganti Tambah Pengguna.

## 14. Contradictions Found in Old PRD/SRS

### Kontradiksi dokumenter yang terselesaikan dalam redaksi

1. Nama/role lama vs tujuh role final: gunakan nama produk dan role aktual.
2. Single-role/single-platform ERD vs pivot: gunakan model relasional final.
3. Manual add konten vs slot kuota: gunakan flow create-slot-submit-deadline-release.
4. Status planned/in_design vs graph final: gunakan sembilan state dan correction terpisah.
